# MoonBind 0.5：从头文件到可复现的消费项目

0.5 把项目接入、显式接口约定和验证记录连在一起。解析、布局、绑定、C 适配层和包装代码生成仍由 MoonBit 实现；`moonbind.py` 是使用 Python 标准库调用编译器、管理模板和保存证据的薄项目驱动层。

## 三步跑通

下载 GitHub 源码发行包或克隆仓库，准备 MoonBit、Python 3.10+ 和 C11 编译器。原生模板面向 LP64 Linux/macOS，Windows 可运行生成、类型检查及报告工具，但 0.5 **不支持 Windows LLP64 原生验证**；doctor 会明确报告不匹配。

```sh
moon update
python moonbind.py init ../my-cjson --template cjson
python moonbind.py validate ../my-cjson
python moonbind.py report-check ../my-cjson
```

打开 `../my-cjson/reports/validation.html` 查看运行结果。初始化拒绝覆盖任何已有目录；可在调用 `validate` 前检查示例代码和接口约定。验证会执行该项目的原生代码。

| 命令 | 行为 |
| --- | --- |
| `init PATH --template NAME` | 在新目录建立完整消费项目，不修改现有目录 |
| `doctor PATH` | 检查 MoonBit、C 编译器、头文件、实际指针/long 宽度和主机目标 |
| `generate PATH` | 根据项目配置生成绑定，保留既有手工编辑保护 |
| `generate PATH --check` | 不写文件，检查生成内容是否过期 |
| `validate PATH` | 生成 → 环境诊断 → native 类型检查 → 编译链接 → 执行声明的运行检查 → 保存 JSON/HTML |
| `report-check PATH` | 对照报告的 SHA-256 快照检查文件变化；失效或失败报告返回非零退出码 |

`--target x86_64|aarch64` 可用于初始化。默认根据主机架构选择；原生验证不执行交叉目标二进制。doctor 不能用“编译器存在”代替“库已链接”，这两个阶段分别记录。

## 五套模板与真实库范围

| 模板 | 验证内容 | 依赖 |
| --- | --- | --- |
| `contracts` | 正常/异常清理、空分配、缓冲区长度、借用字符串复制 | 自包含 C 夹具 |
| `nested` | 嵌套结构体、固定数组、枚举、窄整数、按值返回 | 自包含 C 头文件 |
| `sqlite` | 内存数据库、预处理写入与查询、资源关闭 | 仓库携带 SQLite 源码 |
| `zlib` | `adler32` 的已知校验值与空缓冲区 | 系统 zlib 开发库，Linux 可安装 `zlib1g-dev` |
| `cjson` | 创建/释放数组、读取长度、复制版本字符串 | 固定 cJSON 1.7.19 源码及 MIT 许可证 |

zlib 使用 `Z_SOLO=1` 解析配置，覆盖所选校验接口；这些模板均不宣称覆盖整个库 API。第三方代码、版本和许可证随模板保留。

生成包里 `library.c` 是包含 vendor 源文件的小型编译单元：MoonBit 要求 native stub 位于包内，因此不直接把 `../vendor/library.c` 当成 stub 路径。

## 显式接口约定

这些约定由库使用者填写，工具不凭函数名称猜测所有权。生成前会检查函数是否存在、是否被选择、签名是否符合对应规则。错误约定即使未启用 strict 也会让 CLI 拒绝写入。

```json
{
  "header": "vendor/owned.h",
  "out": "bindings",
  "strict": true,
  "native_sources": ["library.c"],
  "ownership": {"resource_new": "resource_free"},
  "buffers": {"checksum": "data:length"},
  "copy_strings": ["borrowed_text"]
}
```

也可使用 `--own create=free`、`--buffer function=pointer_parameter:length_parameter`、`--copy-string function`。包装函数跟随重命名后的 MoonBit 函数名称。

**作用域清理。** 创建函数需直接返回非字节指针，释放函数需为同一指针类型的 `void(pointer)`。例如生成 `with_resource_new`：

```moonbit
let answer = @lib.with_resource_new(0, fn(handle) {
  @lib.resource_value(handle)
})
assert_eq(answer, Some(42))
```

创建返回 NULL 时得到 `None`，不调用回调。正常返回和 MoonBit `raise` 错误都会释放，然后返回结果或重新抛出错误。不承诺进程终止、abort 或崩溃后的清理。回调不得释放或保存句柄，也不得返回逃逸句柄；MoonBit 类型系统在这里不强制线性生命周期。原始接口仍可用，所以这不是完整内存安全保证。`int close(handle)` 这类带状态返回的释放函数当前会拒绝，需显式提供符合约定的 C 包装函数。

**字节缓冲区。** `_buffer` 包装去掉配置中的长度参数，从对应 `Bytes.length()` 生成 32/64 位整数实参。仅支持字节指针与字节数，不推测元素数、容量、字符串结尾或回调保留行为。调用方须确认 C 函数不会越界或保留指针。

**借用字符串。** `_bytes` 包装立即复制借用的 NUL 终止结果，NULL 保留为 `None`，空字符串为 `Some(b"")`。复制不会释放 C 指针；不要将需要释放的返回值配置为借用字符串。该功能不修复库返回无效指针或未终止字符串的问题。

桥接模式目前可对生成的句柄构造函数或结构体返回函数配置作用域释放，例如 `"mb_Packet_new": "mb_Packet_free"`。缓冲区和字符串约定用于普通绑定模式。

## 扩展结构体适配

0.3 的 `--bridge` 增加以下范围：

- 有符号/无符号 8、16 位整数通过 32 位包装参数传递，读取保留符号；超范围写入终止调用，避免静默截断。
- 枚举值全部位于有符号 32 位范围内的完整枚举。
- 嵌套 struct 和固定长度数组，包括数组中的简单记录。
- 按声明顺序递归展开构造参数；嵌套字段用 `__` 连接，数组下标加入名称，如 `mb_Packet_get_samples__1`。
- 最多八层展开、64 个标量叶子，拒绝过大数组、字段展开后的名称冲突及未支持的结构。

仍拒绝 union、位域、packed/aligned、指针字段、回调和变参桥接。普通模式既有指针接口不受此限制。生成的 C 静态断言检查结构体大小、对齐、字段偏移及叶子字段宽度；必须通过实际编译和调用测试评估自己的头文件配置。

适配层使用相对头文件路径。额外包含目录转换为相对消费模块根目录的编译选项，因此须先建立 `moon.mod`。保持项目内部目录结构时可移动整个项目后编译；如果只复制绑定目录，或改变头文件/宏/目标，应重新生成。跨磁盘根目录不能产生可靠相对路径，会明确拒绝。报告中的路径是诊断记录，不是编译依赖。

## 可追溯验证报告

每次验证记录：

- 工具版本、主机、目标、宏、包含路径及生成配置。
- 函数的预处理 token 来源位置、生成状态及作者声明的测试关联。
- 环境探测、类型检查、编译链接和运行检查各自的命令、退出码和日志。
- 项目输入、生成产物、测试代码和生成器源码的 SHA-256 快照。
- 失败时覆盖旧的成功报告；运行期间源文件变化也会使验证失败。
- 每次验证使用新的构建目录，避免旧 C 目标文件缓存被误当成当前头文件/源文件的验证结果；构建产物保留在消费项目 `_build/validation-*` 中。

`moonbind.project.json` 把运行检查与函数关联：

```json
{
  "schema_version": 1,
  "binding_config": "moonbind.json",
  "runtime_checks": [{
    "name": "resource lifecycle",
    "package": "main",
    "functions": ["resource_new", "resource_free"],
    "verifies": "normal return, raised error and NULL creation"
  }]
}
```

`functions` 是测试作者的声明，工具验证这些函数确实生成并记录检查是否成功，**不会证明每个列出的函数实际被调用或断言充分**。无运行检查时状态为 `compiled_only`，不能标成运行通过；未关联函数显示 `not_tested`。

HTML 离线使用、文本转义、无脚本。打开 HTML 本身不会重新读取文件；依赖结果前运行 `report-check`。报告未签名，不防人为篡改。快照不证明动态系统库、操作系统及外部工具链没有变化；更换环境后应重新执行 `validate`。模板仅包含项目内文件；工具拒绝把未纳入快照的已解析头文件算作完整验证输入。

## 发布检查与试用

```sh
moon test --target wasm-gc
python scripts/verify-v05.py
# LP64 Linux/macOS with clang:
python scripts/verify-v05.py --native
```

原生脚本运行五套消费项目，测试配置/头文件/生成代码/测试代码变化导致报告失效、运行断言失败、链接缺失、项目迁移、相对包含目录、窄整数范围错误，以及嵌套结构体 C 适配层 1,000 次 ASan/UBSan 分配释放。0.3 的原生与布局回归继续保留。

自动化验证不能代替真实用户试用。[试用任务](user-trial.md) 用于两位未参与开发的使用者；发布时不伪造试用人数或反馈。是否完成用户试用以实际记录为准。

## 更新依赖

```sh
moon add --upgrade icyaaaww/moonbind@0.5.0
```

Mooncakes 发布可复用的 MoonBit 包；项目驱动命令从 GitHub 源码发行包使用。`CModule` 新增 `function_locations`，`Options` 新增 `ownership`、`buffers`、`copy_strings`；手工完整构造这些公开结构的调用方需要补齐字段。现有 0.2/0.3 管理状态仍可迁移，原来的 CLI 工作流和比较规则保留。
